# 통합 투명 연출 - 부위 비침(고스팅) 원인 분석 -> 해결 -> 증거

> ★ 이 레포가 증명하는 두 실무 문제 중 하나. 멀티 파츠 스켈레톤을 통째로 페이드할 때 생기는
> 부위 비침(고스팅)을 PMA 블렌딩 관점에서 짚고, 오프스크린 RT 평탄화로 해결한 과정.

## 맥락
Spine 캐릭터는 머리/몸통/팔/다리 등 **반투명 파츠 수십 장이 겹쳐** 한 몸을 이룬다.
등장/퇴장/은신/사망 같은 연출에서 캐릭터 전체를 페이드시키는 일이 잦은데, 가장 단순한 방법은
모든 슬롯의 알파에 그룹 알파 g 를 곱하는 것이다. 이 단순한 방법이 곧 문제를 일으킨다.

---

## 1. 문제 (증상)
g 를 1 -> 0 으로 낮추면 캐릭터가 균일하게 옅어지는 게 아니라 **안쪽 파츠가 바깥 파츠를 뚫고
비쳐 보인다.** 겹친 부위(몸통 뒤의 팔, 머리 뒤의 머리카락 등)가 유령처럼 드러나고, 겹침이 많은
곳일수록 더 진하게 남아 실루엣이 얼룩진다. 이게 "고스팅".

## 2. 원인 분석 - 슬롯마다 알파를 곱하면 차폐가 깨진다

Spine 은 파츠를 **뒤에서 앞으로(painter's order)** 그리며 premultiplied alpha 로 합성한다.
블렌드는 `One / OneMinusSrcAlpha`, 즉 `dst = src + dst * (1 - srcA)`.

- **불투명(g = 1):** 앞 파츠의 srcA = 1 이면 `dst * (1 - 1) = 0` 이라 뒤 파츠 기여가 완전히 가려진다.
  겹친 부위에서 앞이 뒤를 정상 차폐 -> 우리가 보는 정상 캐릭터.
- **그룹 페이드(슬롯마다 g 곱):** 앞 파츠의 srcA = g 가 되면 `dst * (1 - g)` 만큼 뒤 파츠가
  **그대로 새어 나온다.** k 장이 겹친 픽셀의 최종 커버리지는 g 가 아니라 `1 - (1 - g)^k` 라서,
  겹침이 많을수록 더 불투명하게 남고 숨어야 할 안쪽 파츠 색이 섞인다.

즉 **"파츠별 알파 곱"은 레이어 간 차폐 관계를 깨뜨린다.** 각 레이어를 따로 반투명화하니 원래
가려졌어야 할 안쪽이 비치고, 겹침 수에 따라 농도가 들쭉날쭉해진다. 페이드는 **캐릭터 한 장**에
걸어야 맞는데, 멀티 파츠라 애초에 "한 장"이 아닌 게 근본 원인이다.

## 3. 해결 - FadeGroup (오프스크린 RT 로 먼저 평탄화)

핵심은 **페이드 전에 캐릭터를 한 장으로 합치는 것**:

1. 스켈레톤을 **불투명(g = 1)** 으로 오프스크린 RT 에 1회 렌더(`SkeletonRtEffect`). 이 안에서 파츠 간
   차폐가 정상 해결되어, RT 에는 **내부 겹침이 사라진 평면 premultiplied 한 장**만 남는다.
2. 원본은 `MeshRenderer.forceRenderingOff` 로 숨기고, 같은 화면 위치에 그 RT 를 입힌 쿼드를 그린다.
3. 쿼드를 **단일 알파 g 로** 페이드(`SpineFadeComposite`): `col.rgb *= col.a; return tex * col;`.
   레이어가 하나뿐이라 모든 픽셀이 같은 비율로 옅어진다 -> 비침 없는 균일 페이드.

구현 메모:
- 2차 카메라 없이 `CommandBuffer.DrawMesh` 로 RT 에 그린다(카메라 스폰/세팅 부담 없음).
- RT 는 캐릭터의 스크린 AABB 크기로 `RenderTexture.GetTemporary`, 화면 위치/투영을 맞춰
  쿼드에 매핑한다(`SkeletonRtEffect.CalculateProjectionMatrix`).
- **페이드 중(g < 1)에만** 활성. g >= 1 이면 RT 해제 + 원본 일반 렌더로 복귀 -> 안 쓸 땐 비용 0.
- PMA 일관성: RT 가 premultiplied 결과이고, 합성 셰이더도 `col.rgb *= col.a` 로 단일 알파를
  premultiplied 로 만들어 곱하므로 블렌드(One/OneMinusSrcAlpha)가 그대로 성립한다.
- RT 캡처 베이스(`SkeletonRtEffect`)는 전체 윤곽 아웃라인(`SkeletonOutlineRt`)과 공유한다 -
  "캐릭터를 한 덩어리로 다루는" 효과의 공통 토대.

### 왜 naive 경로를 남겨 뒀나
`SpineFxController.Fade(alpha, useGroup:false)` 로 **부위별 알파(고스팅) 경로를 일부러 유지**한다.
같은 화면에 naive vs FadeGroup 을 좌우로 띄워 원인과 효과를 그대로 보이는 게 대표 비교 컷이다.

## 5. 한계 / 확장
- **다중 동시 페이드:** 인스턴스마다 RT 1장이라 동시에 많이 페이드하면 RT/대역폭이 늘어난다.
  공유 RT 나 풀로 묶는 최적화 여지가 있다(현재는 페이드 중인 인스턴스 한정이라 실사용 부담은 작음).
- **투영 가정:** 2D 정면 기준(평균 깊이 평면 투영). 강한 원근/회전에는 별도 처리가 필요하다.
- **해상도:** RT 가 스크린 AABB 기준이라 화면을 꽉 채운 캐릭터는 RT 도 커진다. `_maxRenderTextureSize` 로 상한.
- **부분 페이드 불가:** 캐릭터를 한 장으로 합치므로 "특정 슬롯만 페이드"는 이 경로로 안 된다
  (그건 의도적으로 naive 경로의 몫).
